arXiv Code Model

Speculative decoding lets a small model draft and a large model verify. ProVe reverses the roles: the large model proposes a block of 16 tokens in one forward pass, and a verifier reads it in one more.

How it works

One cycle, with real tokens

The proposer sees the context plus 16 placeholders and fills all of them in one forward pass. A verifier then reads the whole block in one more pass and scores every token after seeing the tokens before it. The longest run that passes the gate is committed.

ProVe

A smaller stock AR model verifies. Gate on p̃ · q ≥ θ: the proposer's confidence times the verifier's probability. Lower θ commits longer runs and trades a little accuracy for speed.

lossy · tunable · one extra small pass

ProVe-lossless

The proposer verifies itself. Its second pass yields the greedy next token after every prefix; at the first disagreement that token is committed instead. Every committed token lies on the greedy AR path.

exact · no threshold · no second model

Why verify

Confidence cannot see the block it judges

The proposer's confidence is computed from placeholders, before the proposed tokens exist. It is free, but it leaves most of the usable block on the table. A verifier reads the realized tokens, and one teacher-forced pass scores all 16.

Cost

The small model runs once per block, not once per token

Count one proposer pass as 1 and a small-model pass as ρ (0.34 for a 3B next to a 32B). Speculative decoding pays ρ for every drafted token. ProVe pays it once.

Recipe

What it takes

Proposer
Qwen2.5-32B-Instruct, fine-tuned with MARS: one epoch of ordinary SFT, then one epoch of block training with 16 placeholders, both on Dolci. Same transformer, same output head, no extra module. It costs 0.6 points of ordinary AR accuracy.
Verifier
Any stock Qwen2.5-Instruct model that shares the tokenizer (3B or 7B), or the proposer itself for ProVe-lossless. Fine-tuning the verifier on the proposer's outputs commits 6–10% more tokens per cycle at the same error rate.
Serving
One SGLang-based engine. Each cycle is two passes. Tokens that are not committed are dropped from the KV cache, so the cache after a cycle equals what AR decoding would have produced.
